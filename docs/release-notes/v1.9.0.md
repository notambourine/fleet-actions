## Action required: declare `cache-mode:` on low-trust triggers

actionlint now requires an explicit cache ceiling wherever a workflow calls a reusable
workflow on `pull_request_target`, `issue_comment`, or `workflow_run`. If your `fleet-ci`
call runs on one of those triggers, this release fails the `actionlint` gate with
`cache-call-unrestricted` until you set the key.

Add `cache-mode:` to the calling workflow, or to the job that makes the call:

```yaml
on: pull_request_target
cache-mode: read

jobs:
  fleet:
    uses: notambourine/fleet-actions/.github/workflows/fleet-ci.yml@<sha> # v1.9.0
```

`read` restores caches but cannot write them. Use `none` if the call needs no cache at all.
GitHub's default is read-only, but it does not cap a callee that asks for write access, so
the declaration has to be explicit. Workflows on `pull_request` and `push` are unaffected.

Two related checks also run now. `cache-write-untrusted` reports an explicit write grant on
those same triggers, and `cache-operation` reports an `actions/cache` step whose operation
your declared mode disables. GitHub skips those silently today.

Set `actionlint-cache-policies: false` to turn all three off.
